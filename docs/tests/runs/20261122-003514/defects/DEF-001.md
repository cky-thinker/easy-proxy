# DEF-001 构建脚本将原生命令警告误判为失败

## 基本信息

| 字段 | 值 |
| --- | --- |
| 缺陷编号 | `DEF-001` |
| 严重级别 | P2 |
| 首次发现运行 | `20261122-003514` |
| 触发用例 | T-37 |
| 修复提交 | `ec2342d14a4ad71407013e4c913118f420b9223f` |
| 验证运行 | `20261122-003612` |
| 状态 | 已关闭 |

## 现象

PowerShell 7 将 Maven、Java 和 WSL 写入标准错误流的警告包装为 `NativeCommandError`。构建脚本在 `$ErrorActionPreference = 'Stop'` 下提前终止，尚未生成 Maven 日志和 Docker 镜像。

## 影响范围

- T-37 正式构建前置被阻断。
- T-38、T-39 及全部部署和下游测试无法开始。
- 业务代码未执行，不能据此判定业务功能失败。

## 根因

原生命令输出被合并到 PowerShell 成功输出流后，PowerShell 依据当前错误偏好设置将部分标准错误文本解释为终止错误；脚本未以原生命令退出码作为唯一成功判据。

## 修复说明

在调用原生命令期间临时关闭原生命令错误偏好，保留标准输出与标准错误合并归档，并在调用结束后恢复原设置。命令是否成功改由 `$LASTEXITCODE` 判定。
