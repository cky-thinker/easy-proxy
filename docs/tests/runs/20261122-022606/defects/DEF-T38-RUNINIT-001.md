## 现象

使用全新运行编号执行 `push-existing-images.ps1` 时，脚本在读取 ACR 凭据前终止：

```text
运行目录不存在：F:\workspace\my\easy-proxy\docs\tests\runs\20261122-022606
```

## 影响

- T-38 推送流程被阻断，无法进入本地镜像预检和 ACR 登录步骤。
- 本轮未读取凭据、未登录 ACR、未推送镜像、未修改远端仓库。
- 该问题属于测试工具缺陷，不涉及已构建镜像内容。

## 根因

脚本要求调用方预先创建运行目录，但方案规定每次执行使用全新 RunId，脚本自身未负责初始化标准运行目录。

## 修复方案

- 当运行目录不存在时，由脚本自动创建运行目录及 registry、validation、processed 和 tmp 子目录。
- 保留已有目录不覆盖行为。
- 使用 PowerShell 语法检查和全新 RunId 推送轮次完成回归。

## 验证证据

- 首次失败：`docs/tests/runs/20261122-022606/raw/validation/t38-push-start.txt`
- 回归方式：修复提交后使用全新 RunId 重新执行 T-38，必须完成三镜像推送、远端清单验证和 ACR 注销核验。
